# Professional Machine Learning Engineer Certification

A Machine Learning Engineer designs, builds, and productionizes ML systems to solve business challenges. This certification learning path provides the advanced knowledge and practical skills required for this role, preparing you to successfully operate and maintain ML systems on Google Cloud.

Through a curated collection of on-demand courses, labs, and skill badges, you will gain real-world, applied experience with Google Cloud technologies. This path focuses on the essential skills for the ML Engineer role, from designing and building ML systems to optimizing and maintaining them in production.

#### Designing high performance ML systems
Distributed training architectures, faster input pipelines, inference, TF distributed training strategies: Mirrorred/Multi-worker mirrorred/TPU/Parameter server, training on large datasets with tf.data API
- [Lab] Distributed Training with Keras
tf.distribute.Strategy API provides an abstraction for distributing training across multiple processing units. uses the tf.distribute.MirroredStrategy, which does in-graph replication with synchronous training on many GPUs on one machine. Essentially, it copies all of the model's variables to each processor. Then, it uses all-reduce to combine the gradients from all processors and applies the combined value to all copies of the model. - Define a distribution strategy and set an input pipeline, Create the Keras model, Define the callbacks, Train and evaluate the model.

#### Prompt Design
- prompt is a natural language request (with a persona) submitted to a language model to receive a response back 
- components of prompt : essential (Objective, Instructions), optional (persona, constraints, tone, context, examples, reasoning steps, response format, recap, system instructions, safeguards, input, prefilled response)

    Tone: Go beyond existing usual itineraries, and suggest innovative ways to enhance the experience!

    Input: Customer location: {user input specified here}

#### Fairness and Bias
- Bias is stereotyping, showing prejudice, or favoritism
    - Reporting bias =>  frequency of events, properties, and/or outcomes captured in a dataset does not accurately reflect their real-world frequency 
    - Automation bias => tendency to favor results generated by automated systems over those generated by non-automated systems, irrespective of the error rates of each.
    - Selection bias => dataset’s examples are chosen in a way that doesn’t reflect their real-world distribution - caused due to Coverage bias / Non-response bias, or participation bias, sampling bias
    - Group attribution bias => tendency to generalize what is true of individuals to an entire group to which they belong - in-group / out-group
    - Implicit bias => assumptions are made based on one’s own mental models and personal experiences that do not necessarily apply more generally - confirmation bias / experimenter’s bias
    - Identify Bias - TensorFlow Data Validation Tool, GCP What-If tool, TensorFlow Model Analysis library (TFMA)
        - Metrics: Regression / Classification metrics, Micro/Macro average, False Discovery Rate, Flip Rate/Flip Count, Query / Ranking, Model side-by-side performance comparison
    - Mitigate Bias - 
    **Data Intervention** (Refine data collection pipeline, balance data by resampling (up/down/resample), augmenting with other existing datasets, synthetic data, or new data collection, Relable data upsert/delete labels) 
    **Threshold calibration** defines the proportion of the prediction results by categorizing them into true positives, false positives, false negatives, and true negatives
    **Model remediation** add L1, L2 norms, TF model remediation MinDiff and Counterfactual Logit Pairing (CLP)

#### Interpretability & Transparency
- Interpretability (deeper and wider understanding of models and holistic systems) / Explainability (specific and technical methods) aims to understand machine learning model behaviors in many ways.

- Explaining ML Model
    - Intrinsic - interpreted by examining its structure or learning process - internals are inherently transparent and can be understood without the need for additional tools - feasible with only simple models (or sophisticated visualisations)
    - Post-hoc (after model training)
    Global(entire model): model agnostic (Partial Dependence Plot PDP / Permutation Importance), Hybrid (aggregate local explainations e.g. SHAP integrated gradients), Model specific (Tree-gain based importance, TCAV)
    Local (individual predictions): model agnostic (Shapley values, LIME), model specific (integrated gradients, SmoothGrad, XRAI, Grad-CAM)
